# P2 · KV Cache 与静态批（引入缓存机制）— 阶段笔记

> 状态：**全部验收达成（2026-09-21）**——KV cache + prefill/decode 分离 + 静态批，正确性双证据 + bench 4.8×
> 日期：2026-09-21

## 本阶段结论

- P2 目标：引入 KV cache 消灭 P1 的全量重算开销，prefill/decode 分离的两段式 attention，静态批 padding 拼批。
- **正确性双证据**：
  1. **batch=1 P2 cache vs P1 eager 逐 token 完全一致**（0.5B CPU fp32，32 token）—— KV cache 不改变结果，只省计算
  2. **batch=3 generate_batch vs 逐个 generate 逐 token 完全一致**（3 条不同长度 prompt）—— padding mask + 每请求独立 position_ids 正确
- **性能提升**（0.5B CPU fp32，5 条 prompt × 16 token）：
  - P1 eager 串行: 7861ms
  - P2 cache 串行: 6798ms（1.2×，CPU 上 KV cache 提升小——CPU matmul 瓶颈在计算不在 launch）
  - **P2 batch=5: 1653ms（4.8× vs eager，4.1× vs cache 串行）**——batch 把 5 个请求的 matmul 合并成一次大 matmul
- **浪费率**（P3 动机证据）：padding 7.6%，KV cache 预分配 97.9%（21/1024）

## 文件变更清单

### 新增代码（1 个）

| 文件 | 行数 | 作用 |
| --- | --- | --- |
| `nano_vllm/kv_cache.py` | 62 | 连续预分配 KV cache（故意浪费版） |

**`kv_cache.py` — 实现要点**：布局 `[num_layers, batch, max_seq_len, num_kv_heads, head_dim]`，一开始按 max_seq_len 预分配整块显存，不回收、不分块。`write(layer_idx, k, v, start_pos)` 把 `[b, num_kv_heads, s, head_dim]` transpose 成 `[b, s, num_kv_heads, head_dim]` 写入对应位置；`read(layer_idx, total_len)` 读出 `[b, num_kv_heads, total_len, head_dim]`。`waste_rate = 1 - seq_len/max_seq_len` 作为 P3 动机证据。

### 修改代码（2 个）

- `nano_vllm/models/qwen2.py`：Attention/DecoderLayer/Qwen2Model/Qwen2ForCausalLM 全链路加 `kv_cache`/`is_prefill`/`cache_seq_len`/`attn_mask`/`position_ids` 参数。
  - **Attention**：prefill 时 K/V 写入 cache 后用当前 K/V 做 `is_causal=True` attention；decode 时 K/V 写入 cache 后从 cache 读全部历史 K/V 做 `is_causal=False` attention（query 1 个，key total_len 个）。`attn_mask` 非 None 时传给 SDPA 并强制 `is_causal=False`。
  - **Qwen2Model**：`position_ids` 可选参数（None 时内部从 `cache_seq_len` 生成，保持 batch=1 兼容）；batch>1 时 `expand(b, -1)`。
- `nano_vllm/model_executor/runner.py`：
  - `generate(use_cache=True)` 走 P2 prefill+decode 路径，`use_cache=False` 走 P1 eager 路径（对拍保留）。
  - `_prefill`/`_decode` 两个内部方法封装 cache 读写。
  - `generate_batch`：padding 拼批 + 每请求独立 position_ids + valid_mask 维护 + done 状态。`_build_prefill_mask` 构造 `[b,1,s,s]` causal+padding mask，`_build_decode_mask` 构造 `[b,1,1,total]` padding mask。

## 踩坑记录

1. **padding 请求的 position_ids**：初版用统一 `cache_seq_len=max_prompt`，短请求（"Hello world" len=2）的 decode position_id 从 5 开始而非 2，导致 RoPE 位置编码错误、输出分叉。修复：每请求独立维护 `seq_lens`，构造 `[b, 1]` 的 decode position_ids。
2. **attn_mask 维度**：初版 `full = causal[None,:,:] & attn[:,None,:].bool()` 得到 `[b,s,s]`，与 SDPA 要求的 `[b,1,s,s]` 不匹配。修复：`causal[None,None,:,:] & attn[:,None,None,:].bool()` → `[b,1,s,s]`。
3. **KVCache batch 维**：初版只有 batch=1（无 batch 维），`write` 用 `k[0].transpose(0,1)`。改成 batch 维后统一为 `k.transpose(1,2)`（`[b,num_kv_heads,s,head_dim]` → `[b,s,num_kv_heads,head_dim]`）。
