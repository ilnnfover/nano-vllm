# P1 · Eager 单流生成（正确性里程碑）— 阶段笔记

> 状态：**全部验收达成（2026-09-21）**——fp32 位级一致 + bf16 实现差异远小于 bf16 固有损失 + greedy 128 token 一致 + bench 6× 对比
> 日期：2026-09-21

## 本阶段结论

- P1 目标：config 驱动的 Qwen2 模型 + safetensors 加载 + 采样器 + 无 KV cache 的自回归循环（每步全量重算），数值路径逐行对齐 HF `modeling_qwen2.py`。
- **正确性三层证据**：
  1. **0.5B 同设备同 dtype（CPU fp32）对拍：29 个张量 diff = 0（位级一致）+ greedy 32 token 逐 token 一致** —— 逻辑（结构/权重加载/RoPE/GQA/tie_emb/采样路径）完全正确
  2. **1.5B 跨设备（GPU fp32 golden vs CPU fp32 nano）对拍：29 个张量 max diff ≤ 3.4e-3（mean ~1e-5），全部 < 1e-2 容差** —— fp32 GEMM 归约顺序差异的正常量级
  3. **bf16 路径正确性验证（0.5B CPU 四组对比）**：HF 自身 fp32→bf16 固有损失 **22.58**，nano bf16 vs HF bf16 实现差异仅 **2.00**（远小于固有损失），nano fp32 vs HF fp32 = **0.0000**。1.5B GPU bf16 hidden_27 diff=3.0 + greedy 128 token 逐 token 一致 → **bf16 diff 是舍入正常累积，非 bug**。
- **KV cache 价值量化（P2 的动机证据）**：同条件 0.5B CPU fp32，nano 重算版 TPOT **441ms** vs HF cache 版 **74ms**（**6×**）。重算版每步把全部序列重跑一遍，这就是 P2 要消灭的开销。

**`config.py` — 实现要点**：frozen dataclass；`from_json` 直接读 HF config.json 顶层字段（不经 transformers config 类）；`head_dim = raw.get("head_dim") or hidden//heads`（1.5B config 无 head_dim 字段，推导值 128 恰为显式值）；`num_kv_groups`/`eos_ids`（int|list 归一为 set）为派生属性；hidden_act 非 silu 直接 raise（P1 范围声明）。

**`models/qwen2.py` — 实现要点**（数值路径逐行照抄 HF 5.x）：
1. RMSNorm：fp32 中 `x * rsqrt(mean(x²)+eps)`，cast 回原 dtype 后再乘 weight（顺序影响数值）。
2. RotaryEmbedding：`inv_freq = 1/(theta^(arange(0,d,2)/d))` fp32 buffer（persistent=False）；forward 中 `inv_freq ⊗ position_ids` 外积 → `cat(freqs, freqs)`（**前后拼接而非交错**）→ cos/sin 在 `torch.autocast(enabled=False)` 强制 fp32 计算，返回时 `.to(x.dtype)`。
3. apply_rotary_pos_emb：cos/sin 沿 head 维 `unsqueeze(1)`，`q*cos + rotate_half(q)*sin`，rotate_half 为 `cat(-x2, x1)`。
4. Attention：QKV **bias=True**（Qwen2 特有）、o_proj 无 bias；`view(b,s,heads,hd).transpose(1,2)`；KV 经 `repeat_kv`（expand+reshape 等效 repeat_interleave，不实际复制内存）展开 6 倍；`F.scaled_dot_product_attention(scale=head_dim**-0.5, is_causal=True)`——与 golden dump 时 HF sdpa 同路径。
5. 结构：DecoderLayer 双 pre-norm residual；Qwen2Model 级共享单个 rotary_emb；`output_hidden_states=True` 时返回 `[embed, L1..LN]` 且 **末元素替换为 final norm 之后**（对齐 HF 5.x 语义，见踩坑 3）。
6. load_weights：自研命名与 HF 完全同名（`model.*`/`lm_head.weight`），映射近乎恒等；tie 时 `weights["lm_head.weight"] = weights["model.embed_tokens.weight"]`（见踩坑 2）；load_state_dict(strict=False) 后 missing/unexpected 双校验。加载前模型已 `.to(dtype)`，copy_ 无 dtype 转换损失。

**`sample/sampler.py` — 实现要点**：temperature<=0 直接 argmax（greedy 零随机）；top-k 用 `topk(...)[0][-1]` 阈值法置 -inf；top-p 用 sort→softmax→cumsum，`mask=(cum-probs)>top_p` 保留首个越界 token，scatter 回原索引；`torch.multinomial(generator=独立 Generator)`，generator 按设备类型创建（CPU generator 不能用于 CUDA tensor）。

**`runner.py` — 实现要点**：`NanoRunner` 持有 config/model/sampler；`forward_last_logits(ids)` 每步传**全序列**（无 cache，这就是最差基线的设计）；`generate()` 循环 argmax/采样，eos 集合来自 config。

**`dump_nano.py` — 实现要点**：输入 ids 从 `--ref` golden 的 meta.json 读取（绝对保证与 HF golden 输入一致）；dump 格式与 dump_hf 完全对称；greedy 循环含 eos（对齐 HF generate 语义），eos 集合并入 generation_config（见踩坑 6）。

## 踩坑记录（本阶段干货最多的一节）

1. **`state_dict()` 对共享参数不去重**：`lm_head.weight = embed_tokens.weight`（tie）后，`named_parameters()` 去重只报一处，但 `state_dict()` 遍历模块树会包含两个键。于是 `load_state_dict(pop 掉 lm_head)` 报 `missing: ['lm_head.weight']`——明明共享却还要"存在"。修复：tie 时把 embed 权重复制一份给 lm_head 键（copy_ 到同一 Parameter 两次，幂等）。
2. **HF 5.x 的 `output_hidden_states` 末元素是 final norm 之后的输出**（4.x 时代 norm 前后被区别对待的行为差异）。表现为：24 层全 diff=0、logits diff=0、唯独 hidden_24 差 193——因为一边是 norm 前一边是 norm 后。验证方法：把自研的 norm(最后一层输出) 与 HF 末元素比，diff=0 即证实。修复：`all_hidden[-1] = norm(hidden_states)`。
3. **HF `generate()` 默认走 KV cache 增量路径**，与全量重算的 kernel/归约顺序在 fp32 下也有 ~1e-6 差异；top-2 接近时 argmax 翻转，自回归输出从分叉点开始彻底不同。对拍判据必须是**同路径**：dump_hf 加 `use_cache=False`（0.5B 修复后 32 token 位级一致）。
4. **`generation_config.json` 的 `repetition_penalty=1.1` 在 `do_sample=False` 时仍生效**——HF 的"greedy"不是纯 argmax！Qwen 官方 generation_config 带此字段，导致对拍在第 6 步（首次 token 重复处）分叉。修复：golden 定义为纯 greedy（`repetition_penalty=1.0`），并在 P1 笔记中记录该语义约定。
5. **eos 是列表不是单值**：generation_config `eos_token_id=[151645, 151643]`，自研只用 config.json 的单值会在停止条件上与 HF 不一致。归一为 set 合并处理。
6. **torch bf16 权重加载顺序**：模型先 `.to(dtype)` 再 `load_state_dict`（copy_ bf16→bf16 无损）；若先加载后转型，fp32 存储的"bf16 值"权重会走不同 GEMM 路径，对拍必挂。
7. WSL2 GPU 透传今日再次间歇性失效（`wsl --shutdown` 可解）——工程上依赖 GPU 的验证步骤都设计了 CPU 降级路径（0.5B fp32 自检、1.5B fp32 跨设备对拍）。
8. **bf16 hidden diff=3.0 的定性判断**：1.5B GPU bf16 对拍 hidden_27 max diff=3.0，初看像 bug，逐层二分定位到 RoPE cos/sin（diff=0.578）。但 cos/sin 只依赖 inv_freq + position_ids（不依赖 x），CPU fp32 位级一致已证明逻辑等价。最终用 `verify_bf16_noise.py` 四组对比定性：bf16 相对 fp32 的**固有精度损失就有 22.58**，nano vs HF 在 bf16 下的 2-3 diff 完全是舍入正常累积。**教训：bf16 下逐层 diff 的绝对值无意义，必须与 bf16 固有损失对比才有意义；greedy 逐 token 一致才是功能正确性的硬判据。**
