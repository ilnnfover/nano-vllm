## 架构设计（grill-me 6 Branch 锁定）

### B1：engine/ 三层架构
- `sequence.py` / `scheduler.py` / `core.py` 三层分离
- `runner.py` 退化为纯执行器（模型加载 + KV cache + sampler）
- `EngineCore.step()` 同步单线程（async 留 P5）

### B2：迭代级调度 + 三态状态机 + 抢占 recompute
- Sequence 三态：WAITING → RUNNING → FINISHED
- 每次 step 重新调度，任意时刻可插入新请求
- 抢占：LIFO 选最新请求回退到 WAITING，从头 recompute

### B3：token budget + LIFO 抢占 + watermark
- 统一 token budget 记账（初始 2048）
- 抢占保留 watermark（预留 1 block 防死锁）

### B5：chunked prefill 动态 chunk + decode 优先 + 混合 mask
- chunk 大小受 `max_num_batched_tokens` 限制
- decode 优先调度（decode 廉价，prefill 让路）
- chunked prefill 混合 mask：query 是 prompt 后缀 [kv_len-q_len, kv_len)，右对齐 causal

## varlen prefill 拼批（核心优化）

### 动机
P4 初版 prefill 逐条执行（每条一次 model forward），8K prompt 串行导致 GPU 利用率低，
吞吐仅 1.93× 未达标。varlen 拼批把本 step 所有 prefill chunk 扁平拼接成一条序列，
一次 model forward 算完。

### 关键洞察
**varlen 拼批的收益主要来自 MLP + QKV proj 一次算完**（旧版 12 条请求 = 12 次完整 forward，
新版 1 次 forward 对 total_q 个 token 一次算完），而非 attention kernel 本身。
即使 `varlen_prefill_torch` 内部逐条循环算 attention，model 其他部分已拼批，收益已经足够。

### 两种后端
- **torch**（`varlen_prefill_torch`）：逐条 gather KV + 右对齐 causal attention（CPU 可测 oracle）
- **flashinfer**（`varlen_prefill_flashinfer`）：`BatchPrefillWithPagedKVCacheWrapper`，
  KV 以 tuple (k_cache, v_cache) 传入，NHD 布局与 P3 PagedKVCache 完全兼容

### flashinfer 冷启动失真修正
旧版 bench（无 warmup）测得 flashinfer 1.07×，误判为"wrapper 开销导致慢"。加 warmup 后真实性能显现：**flashinfer 2.92× 反超 torch 2.85×**（69.19 > 47.57 tok/s）。原因是 flashinfer kernel 首次创建 + JIT 编译有冷启动开销，warmup 轮丢弃后消除。**教训：benchmark 必须 warmup**（此项目第二次踩坑，第一次是 P3 Triton 2.42× 实为 1.51×）。

## 踩坑记录

1. **Write 工具内容重复写入**：`varlen_prefill.py`、`core.py`、`bench/p4_bench.py` 都出现过
   Write 把文件内容写两遍导致语法错误（`from __future__` 出现在文件中间）。
   修复：截取前半部分或重新 Write 单份内容。

2. **抢占时 victim 未从 scheduled 列表移除**：Scheduler step 2 抢占后 victim 仍在
   scheduled 列表里，导致 token_budget 双重扣减。修复：抢占时从 scheduled 移除 victim +
   恢复 token_budget。

3. **flashinfer 冷启动失真**：旧版 bench 无 warmup，flashinfer kernel 首次创建 + JIT
   编译开销导致 1.07× 误判。加 warmup 后真实 2.92× 反超 torch。**benchmark 必须 warmup**。

4. **bench TPOT 测量缺陷（已修复）**：旧版 `bench_tpot` 只测 wall_ms，不是 TPOT p99。
   新版手动展开 step 循环，记录纯 decode step 间隔 p99（排除 prefill step）。
   修复后 chunked 不劣化 decode（torch 0.999× / flashinfer 0.822×）。
