## 本阶段结论

- P5 目标：把 P4 的同步 `EngineCore` 包装为 **async 引擎**，通过 **FastAPI** 暴露
  OpenAI 兼容 API（`/v1/completions` + `/v1/chat/completions`，含 streaming），
  HTTP 吞吐损耗 < 10%。
- **正确性（CPU fp32）**：4 项测试全绿（`tests/test_p5_serving.py`）
  1. 非流式 `/v1/completions` 返回完整文本
  2. 流式 `/v1/completions` 拼接 == 非流式输出
  3. 非流式 `/v1/chat/completions` 返回 assistant 消息
  4. 流式 `/v1/chat/completions` 拼接 == 非流式输出
- **吞吐验收（CPU 0.5B fp32, warmup+repeat 中位数）**：HTTP 反超直连（ratio 1.20）
  — 原因是 `asyncio.to_thread(step)` 让 step 在线程池跑，主线程可并行做 JSON 序列化。
  GPU 上差异预计更小（GPU 计算异步，HTTP 开销占比更高）。**GPU bench 待用户跑**。

## 架构设计（grill-me 4 Branch 锁定）

### B1：async 架构 — AsyncEngineCore 包装 EngineCore
- 新建 `AsyncEngineCore` 包装同步 `EngineCore`，**不改原生 EngineCore**
- `asyncio.to_thread(step)` 把同步 step 扔线程池，避免阻塞 event loop
- 后台单 step 循环 task 独立于 `generate()` / `generate_stream()`

### B2：streaming 取 token — step() 返回 (finished, sampled)
- 改 `EngineCore.step()` 返回 `tuple[list[Sequence], dict[int, int]]`
- `sampled` 是每步产出的 `{seq_id: token_id}`，供 streaming 逐 token 分发
- `generate()` 用 `finished, _ = self.step()` 自动兼容（P4 测试 4/4 仍全绿）

### B3：路由 + streaming — 后台 step 循环 + Queue 分发
- 两路由 `/v1/completions` + `/v1/chat/completions`，各支持 `stream=True/False`
- OpenAI 兼容 SSE：`data: {json}\n\n` + `data: [DONE]\n\n`
- **后台单 step 循环** task 独立于 `generate_stream()`，token 通过 `asyncio.Queue`
  分发给各请求——SSE 发送慢不阻塞其他请求的 token 产出

### B4：验证 + 压测 — CPU 正确性 + GPU HTTP 吞吐
- CPU 正确性：HTTP streaming vs 非流式输出一致（httpx ASGITransport，不起真实 server）
- GPU 压测：HTTP vs 直连吞吐（warmup+repeat，损耗 < 10%）

## 踩坑记录

1. **Write 工具内容重复写入**：`async_engine.py`、`protocol.py`、`p5_bench.py` 都出现
   Write 把内容写两遍导致语法错误。修复：用 python 脚本截取前半部分。

2. **IsolatedAsyncioTestCase 跨 event loop 死锁**：每个测试方法独立 event loop，
   但 `AsyncEngineCore._step_task` 跨 loop 引用导致第二个测试死锁。
   修复：`_ensure_step_loop` 加 `self._step_task.get_loop() is not asyncio.get_running_loop()` 检查，
   loop 不匹配时重建 step task。

3. **apply_chat_template 返回类型**：`tok.apply_chat_template(messages, tokenize=True)`
   在 transformers 5.17.0 返回 `BatchEncoding`（dict-like），不是 `list[int]`。
   修复：改用 `tokenize=False` 返回字符串，再 `tok.encode(text, add_special_tokens=False)`。
