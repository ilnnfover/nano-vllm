## 本阶段结论

- **目标**：块级前缀缓存——相同前缀的请求**跳过重算**直接复用已算好的 KV，并处理引用计数与 COW。
  这是面试高频题（"前缀缓存怎么保证不共享错"）。
- **正确性**：P6 新增 **59 项**测试；全量 `tests/` **94 passed**（无模型/无 GPU 也可跑的部分全部 CPU 覆盖）。
  - `test_p6_prefix_cache_unit.py`（33）：hash / 命中 / 注册 / COW / extra keys / salt / 埋点
  - `test_p6_correctness.py`（4）：开-关缓存输出逐 token 一致 / 命中跳过重算的 token 数 / 抢占×前缀缓存
  - `test_p6_guards.py`（11）：D4 批元数据守卫 + NaN/Inf 守卫
  - `test_p6_throttle.py`（11）：A6 三个节流阀
- **验收（roadmap 修订后的 4 条）**：

| 判据 | 结果 | 证据 |
| --- | --- | --- |
| 同前缀重放 TTFT 显著下降并出数据 | ✅ 4096 前缀 **9.02×** | `p6_bench_gpu_1.5b.json` |
| 开/关前缀缓存输出逐 token 一致 | ✅ | `test_p6_correctness.py::test_shared_prefix_output_identical` |
| COW 分支不可触发 → 单测覆盖 | ✅ 口径已修订 | roadmap §P6 完成标准 + `docs/notes/prefix-cache-partial-hits.md` |
| 命中率统计埋点 | ✅ | `engine/stats.py` 5 个字段 + `Scheduler.prefix_cache_hit_rate` |

- **一句话结论**：前缀缓存主要省 **prefill / TTFT**，不显著提升总吞吐 —— 输出短时 decode 主导总耗时
  （多轮重放 TTFT p50 1.91×，但端到端 wall 仅 1.04×）。与 P4「收益来自拼批而非单算子」是同一口径。

## 架构设计（grill-me Branch 锁定）

### B1 · hash 粒度：只注册满块

滚动 hash `hash[i] = sha256(prev_hash ‖ tokens_i ‖ extra_keys)`，**只注册满块**，partial 块不注册。
对齐 vLLM 纯 Transformer 默认行为（`enable_partial_hash_hits` 默认 False，且要求 Mamba align group）。

理由：partial 块注册后永远是 partial（COW 后请求写的是新块），每次命中都要 COW 复制整块，
`remainder` 小时代价超过收益。**副作用：COW 分支不可达**（见 B4）。

### B2 · 块池双结构（`kvmm/block_pool.py`）

| 结构 | 作用 |
| --- | --- |
| `_free_queue`（`OrderedDict`） | 只装 `ref_cnt == 0` 的块，按 LRU 序 —— 分配来源 + 淘汰顺序 |
| `_hash_index`（`dict[hash → block_id]`） | 含**所有**有 hash 的块（不论 ref_cnt），仅供命中查找 |

被引用块保留索引 → 并发共享前缀都能命中。`touch()` 命中时 `ref_cnt+1` 并从 free_queue 摘除（O(1)）。
`_evict_hashes()` 在块被重新分配前清掉其 hash 索引。**淘汰不清零 KV**：由 torch `[:seq_len]` /
triton `offs_n` 掩码 / varlen `last_page_len` 三处兜底。

### B3 · 命中接入调度（对齐 `KVCacheManager`）

| 方法 | 对齐对象 | 职责 |
| --- | --- | --- |
| `Scheduler.get_computed_blocks(seq)` | `get_computed_blocks(request)` | 查命中前缀（**不改状态**） |
| `Scheduler._attach_hit_blocks(seq, hit)` | （vLLM 合并在 allocate_slots 内） | touch 命中块 + 挂 block_table + 推进 `num_computed_tokens` |
| `Scheduler.allocate_slots(seq, num_new_tokens)` | `allocate_slots(request, num_new_tokens)` | 容量检查与分配 |

注册走增量路径：`update_from_output` 里按 `num_computed_tokens // block_size` 只注册新增满块
（`num_registered_blocks` 记录进度），避免重复算 hash。

**注意**：本引擎在 forward **之后**才注册块 hash，所以**同批并发提交的请求不会互相命中**；
bench/测试必须**按序提交**（前一条 prefill 完成后才提交下一条）才复现命中 —— 这是口径的一部分。

### B4 · COW 的触发面（决策）

COW（`PrefixCache.cow_for_write`、`BlockPool.move_hashes`）**仅 partial 命中时触发**，
而 pure Transformer 下 partial 命中不可达 → **当前无调用者，保留作设计参考**。

vLLM 侧同样如此：`_apply_cow` 只在 partial 命中触发，且 `enable_partial_hash_hits` 要求
Mamba `align` group。**详细源码链路与复刻路径见 `docs/notes/prefix-cache-partial-hits.md`。**
roadmap §P6 的完成标准已据此修订（原「COW 触发时输出逐 token 一致」不可执行）。

### B5 · extra keys / salt

hash 除 token 外纳入 `extra_keys`（请求级，`Sequence.prefix_cache_extra_keys`）与引擎级 `salt`，
用于区分「token 相同但 KV 不该共享」的场景（LoRA adapter / 多模态 / prompt_embeds / 命名空间）。
`hash_block_tokens` 对齐 vLLM 的 `(parent_hash, tokens, extra_keys)`。

- `salt` 只在**链首**生效，后续块经 `parent_block_hash` 继承 —— 与 vLLM 把 `cache_salt`
  只加在 `start_token_idx == 0` 一致。
- 向后兼容：`salt=0` 且 `extra_keys` 为空时 hash 与旧口径**逐字节一致**（有测试守着）。
- 取舍：只支持**请求级统一 extra_keys**；vLLM 多模态按块内偏移取 key 的行为未复刻。

### B6 · 命中率埋点与开关

- `Scheduler` 累计 `prefix_lookups / prefix_query_tokens / prefix_hit_tokens / prefix_hit_blocks`
  → `prefix_cache_hit_rate = hit_tokens / query_tokens`；`reset_prefix_stats()` 供 bench repeat 隔离。
- 口径：引擎级累计命中率**含冷请求**，故上表 `hit_rate`（0.667→0.738）低于暖请求理论值
  `warm_hit_ratio`（0.889→0.985）；两者都在 JSON 里，读曲线时区分。
- 开关：`Scheduler(enable_prefix_cache=…)` + CLI `--no-prefix-cache`（api/p4_bench/p5_bench），
  用于开/关 A/B。

### B7 · 前置遗留回填（D4 / D2 / A6）

- **D4 守卫**：`engine/core.py` 的 `validate_batch_metadata()`（shape/容量自洽，**始终开启**）与
  `check_finite()`（NaN/Inf，`debug` 开关 / `NANO_VLLM_DEBUG=1`），接入全部 4 条执行路径。
  补上了审计点名的缺口：`qo_indptr[-1] == len(input_ids)`。
- **D2 口径**：`bench/run_local.py`、`p3_bench.py`、`p3_longctx_check.py` 的 `argmax` 全部改为
  `Sampler.sample(..., temperature=0.0)` → bench 与 serving 同一条采样路径。
- **A6 节流阀**：`long_prefill_token_threshold`（默认 **0 = 关闭**，与 vLLM 一致）、
  `max_num_seqs`（默认 None）、`watermark_blocks` 缺省改为按比例（`watermark_ratio=0.01`）。

## 踩坑记录

1. **`watermark_blocks` ≠ 小物理池**：想用它模拟紧显存来省掉一次模型加载，结果 watermark 是
   「全局预留」，会让**单条请求也放不下** → 两个请求互相抢占成死循环（实测超时 600 s）。
   抢占测试必须用真实小 `num_blocks` 的 runner。
2. **测试套件内存上限**：各测试文件 `setUpClass` 常驻 0.5B 模型且从不释放，峰值 RSS 达 **14.6 GB**
   （WSL 上限 15.9 GB）。加入 P6 测试文件即 OOM（kill 点会漂移）。加 `tearDownClass` 释放后
   峰值降到 **10.5 GB**。
3. **D2 不会改变数字**：`Sampler.sample(temperature<=0)` 就是 `int(logits.argmax())`，
   与 bench 原写法逐位等价 → 审计文档「数字会变、需重跑 P0–P5」是保守估计。
4. **vLLM 的 `long_prefill_token_threshold` 默认是 0（关闭）**，不是 `budget//2`
   （`vllm/config/scheduler.py:80`）。最初按审计建议把 `budget//2` 写成默认并在注释里称
   "vLLM 同款默认"，核对源码后修正为 0。
5. **A6 的收益在本负载上不成立**：吞吐代价 −17% 稳定可测，而 TPOT p99 改善落在噪声区间内
   （共享桌面 GPU，同配置极差 ~6 ms）。结论要写成区间，不能写成"有效"。
6. **前缀缓存无法靠并发命中**：块 hash 在 forward 后才注册，同批并发提交不会命中；
   bench/测试必须按序提交。这一条不写清，bench 数字会无法解释。
7. **COW 的触发面容易被误判**：vLLM 里 `move_block_hashes` 是**活代码**（Mamba partial tail offload），
   只是纯 Transformer 走不到；不能当成死代码删掉。
